  - **Bug ditemukan di tengah proses**: `prisma migrate deploy` pertama ke branch `production` gagal `P1002` (timeout ambil advisory lock) — branch itu baru pertama kali diakses jadi compute-nya cold-start dari nol (Neon scale-to-zero). Retry kedua langsung sukses; `prisma migrate status` dipakai untuk memastikan attempt pertama tidak meninggalkan state setengah-jadi sebelum lanjut seed
- [x] **Alur staging → production** (permintaan user, setelah demo publik live): user tidak mau perubahan langsung tampil di domain publik tiap kali agent push. Dibuatkan pemisahan 3-tingkat, semuanya lewat mekanisme native Vercel + Neon (tidak butuh tooling tambahan):
  - **Git**: branch baru `staging` dibuat dari `main`, di-push ke GitHub. `main` tetap jadi Production Branch di Vercel (tidak diubah)
  - **Database**: branch Neon ketiga `staging` (di-branch dari `production`, jadi langsung punya data yang sama lewat copy-on-write instan Neon — tidak perlu migrate+seed ulang). Alasan dipisah dari branch `main` (dev): dev lokal pakai `prisma db push` yang tidak tercatat di riwayat migrasi, sedangkan build Preview Vercel pakai `prisma migrate deploy` yang strict terhadap riwayat itu — kalau satu branch dipakai keduanya, drift antara `db push` dev dan `migrate deploy` staging bisa bikin state gak sinkron. Trade-off ini didiskusikan eksplisit ke user sebelum membuat branch ketiga, bukan diasumsikan sendiri
  - **Vercel env vars**: `DATABASE_URL`/`AUTH_SECRET`/`ENCRYPTION_KEY` di-set terpisah di scope **Preview** (bukan Production) — `AUTH_SECRET`/`ENCRYPTION_KEY` digenerate baru, beda dari yang dipakai Production maupun dev
  - **Build Command tidak perlu di-override lagi terpisah** — setting yang di-set untuk Production di awal Fase 16 memang berlaku project-wide (semua environment), jadi Preview otomatis ikut `prisma generate && prisma migrate deploy && next build`, cuma target `DATABASE_URL`-nya beda (resolve ke branch Neon `staging`)
  - **Bug ditemukan**: push pertama branch `staging` ke GitHub tidak langsung memicu Preview Deployment di Vercel (webhook kelewat). Diperbaiki dengan push commit kosong (`git commit --allow-empty`) untuk re-trigger — build langsung muncul setelahnya
  - **Deployment Protection (SSO) Vercel otomatis aktif di Preview** — bagus, sesuai maksud staging (bukan publik), tapi konsekuensinya agent TIDAK BISA verifikasi otomatis (curl/Playwright kena redirect ke `vercel.com/sso-api`, butuh sesi login Vercel). Untuk staging, laporan user diterima apa adanya untuk bagian ini — beda dari verifikasi production yang selalu dicek ulang independen oleh agent
  - Alur kerja final: agent push ke `staging` → Preview build otomatis (migrasi ke Neon `staging`) → user review di URL Preview (perlu login Vercel) → user bilang "apply"/"merge" → agent merge `staging` ke `main` dan push → Production build otomatis (migrasi ke Neon `production`) → domain publik ke-update. Domain publik TIDAK PERNAH berubah dari sekadar push ke `staging`
